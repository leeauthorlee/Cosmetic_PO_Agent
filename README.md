# Cosmetic_PO_Agent

화장품 회사 구매담당자를 위한 **SIL 구매 업무 어시스턴트**입니다. 자연어로 판매량을 예측하고 국내 재고와 비교한 추가 주문량을 그래프·표·CSV로 확인하는 Streamlit 챗봇입니다. PO는 Purchase Order(발주)를 뜻합니다.

현재 국내 3개 채널과 Amazon US의 판매량을 **저장된 XGBoost 모델로 실제 추론**합니다. LLM은 질문 분류, 도구 선택·인자 구성, 결과 설명을 담당합니다. 판매량은 모델 추정치이며 실제 발주를 실행하는 서비스는 아닙니다.

## 1. 프로젝트 배경과 목표

프로젝트는 구매담당자가 광고비·프로모션에 따른 수요 변화를 살펴보고 재고 부족과 과잉 재고를 줄이도록 돕습니다. 기획서의 프로젝트명은 **구매를 최적화하는 챗봇 구축**, 유형은 **채널 운영 코파일럿**입니다.

최종 목표는 향후 4주 판매량 예측을 바탕으로 창고별 재고 소진과 발주 필요 여부를 판단하는 것입니다. 현재 판매량 예측과 국내 추가 주문량 계산은 연결되어 있지만, 재고 소진 날짜·국외 주문량·입고 예정 물량을 반영한 발주 판단은 구현되지 않았습니다. 예측 대상은 매출액이 아닌 판매 수량(units, 개)입니다.

## 2. 현재 구현된 기능

| 기능 | 현재 동작 |
| --- | --- |
| 업무 질문 분류 | 경량 LLM이 판매·재고·주문 관련 질문을 분류합니다. |
| 국내 판매량 예측 | 쿠팡·네이버·자사몰에 국내 XGBoost 모델과 전용 스케일러를 적용합니다. |
| 국외 판매량 예측 | Amazon US에 미국 XGBoost 모델과 전용 스케일러를 적용합니다. |
| 입력 조건 반영 | 제품, 채널, 시작 날짜, 주차 수, 광고비 증감률, 할인율, 프로모션 일수를 반영합니다. |
| 광고비 시나리오 비교 | 광고비 변경 전·후 판매량, 차이, 증감률을 반환합니다. |
| 여러 제품 표시 | 제품·사이트·주차별 예측 결과를 그래프와 상세 표에 표시합니다. |
| 국내 주문량 계산 | 단일 제품의 3주 수량 또는 여러 제품의 예측 기간 총수량을 국내 재고와 비교합니다. |
| 주문 보고서·CSV | 최근 주문 결과 팝업과 현재 필터에 표시된 주문 내역의 CSV 저장을 지원합니다. |
| 대화·분석 탐색 | 새 대화, 현재 대화의 분석 내역 선택, 같은 세션의 이전 대화 복원을 지원합니다. |

### 판매량 그래프와 표

- **전체**: x축은 국내·국외, y축은 판매량입니다. 채널별 누적 막대, 구간 수량·상단 합계, 오른쪽 채널 범례를 표시합니다.
- **Amazon US·쿠팡·네이버·자사몰**: x축은 날짜·요일, y축은 판매량입니다. 제품 SKU별 누적 막대와 오른쪽 제품 범례를 표시합니다.
- 날짜는 일별 판매 날짜가 아닌 **예측 주의 시작일(월요일)**입니다.
- 아마존 그래프는 입력 조건을 적용한 scenario_units를 표시합니다. 상세 표에는 기준 판매량과 판매량 변화도 표시합니다.
- 아마존 기준 시나리오는 광고비 증감률만 0으로 둔 경우입니다. 할인율·프로모션 일수는 변경 시나리오와 동일하므로, 변화량을 할인 효과까지 포함한 전체 프로모션 효과로 해석하면 안 됩니다.
- 필터는 이번 질문에서 이미 조회된 결과만 표시합니다. 필터 선택으로 도구를 새로 호출하지 않으며, 결과가 없다는 것은 판매량이 0이라는 뜻이 아닙니다.

### 재고 주문 화면

제품별 예상 판매량·부족 수량·주문량 비교 그래프와 상세 표를 제공합니다. 국내·국외 필터는 있지만 현재 주문 도구는 모두 KR_WH만 조회하므로 국외 주문 결과는 없습니다. **아마존 판매량 예측 지원과 아마존 창고 주문 계산 지원은 별개입니다.**

CSV 파일명은 sil_inventory_order.csv, 인코딩은 utf-8-sig입니다. SKU, 지역, 창고, 예상 판매량, 부족 수량, 주문량이 포함됩니다. 현재 다운로드 대상은 주문 내역이며 판매량 예측 결과용 CSV 버튼은 없습니다.

## 3. 도구와 데이터 처리 흐름

~~~text
사용자 질문
  → send_message → agent.invoke
  → check_order_question: 업무 관련성 분류
  → 에이전트의 도구 선택
      ├─ 국내 판매량 → predict_sales_kr
      ├─ 아마존 판매량 → predict_sales_us
      └─ 국내 주문량 → check_inventory / check_inventory_batch
  → 도구 결과를 바탕으로 에이전트 답변
  → extract_display_results: 이번 질문의 도구 결과 추출
  → build_sales_chart / render_results: 그래프·표·주문 CSV 표시
~~~

도구 호출은 고정된 파이프라인이 아니라 LLM이 시스템 프롬프트와 대화에 따라 선택합니다. 국내외 모두를 요청하면 두 판매량 도구의 결과가 필요합니다. 프롬프트는 채널 미지정 시 국내외 예측을 안내하지만, predict_sales_kr(channel=None) 자체의 범위는 국내 3개 채널입니다.

| 구성 요소 | 역할 |
| --- | --- |
| gpt-5.4-mini | 메인 에이전트의 도구 선택 및 답변 |
| gpt-5.4-nano·QuestionFilter | 질문 관련성 분류 |
| create_future_dates | 시작 날짜를 월요일로 보정하고 주차 생성 |
| create_future_dataset | 국내 모델용 12개 입력 컬럼 생성 |
| create_future_dataset_us | 미국 모델용 9개 입력 컬럼과 제품·날짜 정보 생성 |
| predict_sales_kr | 국내 모델 추론, 전체·주차·제품별 집계 및 상세 결과 반환 |
| predict_sales_us | 미국 기준·변경 시나리오 추론, 차이·증감률·상세 결과 반환 |
| load_inventory_data·find_inventory_data | 재고 CSV와 제품 정보를 결합하고 국내 재고 조회 |
| calculate_order_quantity | 부족량과 500개 단위 추가 주문량 계산 |
| check_inventory | 단일 SKU와 1~3주 수량을 받아 주문량 계산 |
| check_inventory_batch | SKU별 예측 총수량 목록으로 여러 제품의 국내 주문량 계산 |
| InMemorySaver·thread_id | 세션별 대화 문맥 유지 |
| extract_display_results | 국내·미국 상세 예측과 주문 결과를 화면용 행으로 변환 |
| show_order_report | 최근 주문 결과를 팝업으로 표시 |

### 입력값과 기본 동작

| 인자 | 동작·기본값 |
| --- | --- |
| sku | 미지정 시 해당 도구의 전체 제품. 국내는 문자열 또는 목록, 미국은 단일 문자열을 받습니다. |
| channel | 국내 도구 전용. coupang, naver, own_mall 및 한글 이름 지원. 미국 도구는 Amazon US 고정입니다. |
| weeks | 두 판매량 도구 모두 기본 1주입니다. 4주 예측은 weeks=4로 요청합니다. |
| start_date | 지정 날짜가 속한 주의 월요일부터 예측합니다. |
| start_after_weeks | 날짜 미지정 시 도구가 참조하는 판매 데이터 마지막 주에서 N주 뒤. 기본 1입니다. 현재 날짜 기준이 아닙니다. |
| ad_spend_change_pct | 마지막 관측 주 광고비 대비 증감률. 기본 0, 10이면 10% 증가입니다. 절대 광고비 입력 인자는 없습니다. |
| promo_discount | 0~1, 예: 30%는 0.3. 미지정 시 마지막 관측 값 유지. |
| promo_days | 주간 프로모션 일수 0~7. 미지정 시 마지막 관측 값 유지. |

미지정 광고비·프로모션 조건은 제품·채널별 마지막 판매 이력의 값을 기준으로 만들며, 생성한 조건을 각 미래 주에 반복 적용합니다. 실제 향후 주차별 계획 파일을 자동으로 불러오는 방식은 아닙니다. 국내 광고비·가격은 KRW, 아마존은 USD를 사용합니다. 같은 주·채널의 광고비가 제품 행마다 반복되므로 제품별로 합산해 채널 총예산으로 해석하지 않습니다.

### 국내 주문량 계산

~~~text
단일 제품: 예상 판매량 = sales_week1 + sales_week2 + sales_week3
일괄 계산: 예상 판매량 = 제품별 전달받은 predicted_units
부족량 = max(0, 예상 판매량 - KR_WH의 on_hand)
표시 부족 수량 = ceil(부족량)
주문량 = ceil(부족량 / 500) × 500
~~~

check_inventory_batch에는 국내 예측의 product_predictions를 전달할 수 있습니다. 국내 도구를 전체 채널로 호출한 경우 제품별 집계에는 국내 3개 채널 수요가 포함됩니다. 개별 채널을 따로 호출했다면 도구에 전달하기 전에 동일 SKU의 수요를 합쳐야 합니다. 일괄 도구는 중복 SKU를 합산하지 않고 첫 항목만 처리합니다.

미입고 발주량, 리드타임, 안전재고, 제품별 최소 주문 수량은 현재 계산에 반영하지 않습니다. 미국 판매량을 국내 주문 도구에 전달하면 창고 기준이 달라지므로 국내 수요와 구분해야 합니다.

## 4. 데이터와 모델 파일

현재 앱에서 사용하는 데이터는 data/, 모델은 models/ 아래에 있습니다.

| 파일 | 역할 |
| --- | --- |
| data/sales_weekly.csv | 판매 이력, 예측 기본 광고비·프로모션 및 날짜 기준 |
| data/product_master.csv | SKU별 원화·달러 정가, 제품명 등 기준 정보 |
| data/inventory_now.csv | 국내 현재 재고 조회. 다른 창고 행도 있지만 현재 주문 도구는 국내만 사용 |
| models/xgbr_model_k.joblib | 국내 XGBoost 모델 |
| models/minmax_scaler_k.joblib | 국내 모델 전용 MinMaxScaler |
| models/xgbr_model_u.joblib | 미국 XGBoost 모델 |
| models/minmax_scaler_u.joblib | 미국 모델 전용 MinMaxScaler |
| cosmetics_sales_rate.ipynb | 데이터 탐색·전처리·모델 학습·평가·저장 코드 |

국내 입력은 SKU, 광고비, 프로모션 일수·할인율, 분기·연도·월·일, 프로모션 가격, 국내 채널 원핫 3개로 총 12개입니다. 미국 입력은 채널 원핫을 제외한 9개입니다. SKU 숫자 매핑과 컬럼 순서는 학습 시점과 일치해야 하며, 모델과 스케일러는 같은 학습 결과의 쌍을 사용해야 합니다.

models/의 sales_model.json, sales_prediction.pkl, best_dl_model.h5는 현재 앱의 직접 로딩 대상이 아닙니다. future_plan_4w.csv, submission_template.csv, reviews.csv 등은 학습 노트북·원본 과제 자료와 관련된 파일이며 현재 실행용 data/에는 포함되지 않습니다. 노트북 전체 실행에는 해당 추가 데이터가 필요합니다.

원본 과제의 가상 기준일은 2026-07-26, 4주 평가 기간은 2026-07-27~2026-08-23입니다. 제품 5개 × 채널 4개 × 4주이면 총 80개 예측 행입니다. 이 과제 기준일과 실제 실행일을 구분해야 합니다.

## 5. 실행 방법

프로젝트 루트에서 실행합니다. 다음은 Windows PowerShell 기준입니다.

~~~powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
~~~

기존 가상환경이 준비되어 있다면 생성 단계는 생략합니다. 프로젝트 루트의 .env에 API 키를 설정합니다.

~~~dotenv
OPENAI_API_KEY=your_api_key_here
~~~

코드에 설정된 LLM을 호출할 수 있는 API 환경이 필요합니다. 키가 포함된 .env는 공유하거나 커밋하지 않습니다.

~~~text
Cosmetic_PO_Agent/
├─ app.py
├─ README.md
├─ requirements.txt
├─ cosmetics_sales_rate.ipynb
├─ data/
│  ├─ sales_weekly.csv
│  ├─ product_master.csv
│  └─ inventory_now.csv
├─ models/
│  ├─ xgbr_model_k.joblib
│  ├─ minmax_scaler_k.joblib
│  ├─ xgbr_model_u.joblib
│  └─ minmax_scaler_u.joblib
├─ assets/
│  ├─ sil-logo.png
│  ├─ taekwang-wordmark.png
│  └─ safin-banner.png
└─ .env
~~~

~~~powershell
.\.venv\Scripts\python.exe -m streamlit run app.py
~~~

CSV와 모델 경로는 상대 경로이므로 프로젝트 루트에서 시작해야 합니다. 두 지역의 모델·스케일러는 앱 시작 시 로드되므로 국내만 조회하더라도 미국 파일도 필요합니다. 이미지 파일은 존재 여부를 확인하여 표시합니다.

모델 로딩 오류가 발생하면 파일 경로·파일 상태와 학습 환경의 Python/XGBoost/scikit-learn 버전을 먼저 확인합니다. 모델·스케일러 파일만 다른 학습 결과로 교체하거나 컬럼 순서를 임의로 변경하지 않습니다.

### 질문 예시

- 2026-11-02부터 4주간 A-SRM-100의 쿠팡 판매량을 예측해줘.
- 2026-11-02부터 3주간 국내 전체 제품의 판매량과 추가 주문량을 계산해줘.
- 2026-11-02부터 4주간 아마존 전체 제품의 광고비를 10% 늘렸을 때 판매량과 증가분을 알려줘.
- 2026-11-02부터 3주간 국내 전체 채널과 아마존의 제품별 판매량을 각각 예측해줘.
- 2주 뒤 재고 주문량 예측해줘.

전체 그래프에 국내외를 함께 보려면 같은 질문에서 두 지역의 예측 결과가 반환되어야 합니다. 이전 대화 결과를 자동으로 합산하지 않습니다.

## 6. 학습·평가 현황과 한계

현재 노트북은 품절이 없는 행(stockout_days == 0)으로 학습 데이터를 구성하고, 국내·미국을 분리하여 스케일러와 모델을 학습합니다. 학습·평가 분할은 train_test_split의 무작위 분할이며 국내 테스트 비율은 20%, 미국은 10%, random_state=100입니다. MAE, MSE, R² 평가 코드가 있습니다. 앱은 저장 모델을 추론에 사용할 뿐 재학습이나 성능 평가를 실행하지 않습니다.

원본 과제의 시간 순서 검증과 최근 4주 평균 대비 WAPE 비교는 현재 구현된 무작위 분할과 구분해야 합니다. 향후 과거 기간으로 학습하고 이후 4주로 평가하는 검증을 추가해야 합니다.

~~~text
WAPE(%) = Σ|실제 판매량 - 예측 판매량| / Σ실제 판매량 × 100
~~~
